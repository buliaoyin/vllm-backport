# 普通投影 FP16 缓存消融（2026-09-11）

**从推荐的 INT8 + chunk 6144 组合中移除普通投影 FP16 缓存。** 固定分层的正反序对照中，缓存对 64K 输入吞吐贡献约 **0.85%**，TTFT 缩短约 **117 ms**，代价是三张 SM80 合计 **10.09 GiB** 常驻 FP16 权重副本。

## 同配置实测

单位为输入 token/s，即 `prompt_tokens / TTFT`，取中位数。8K–32K 每配置各 3 次；64K 合并正反序测量，每配置各 8 次。所有测量均不带 event profiler。

| 输入 | 关闭缓存 | 开启缓存，预算 4 GiB/SM80 | 缓存收益 |
| --- | ---: | ---: | ---: |
| 8K | 2176.3 | 2200.7 | 1.12% |
| 16K | 3165.4 | 3189.6 | 0.77% |
| 32K | 4018.3 | 4061.4 | 1.07% |
| 64K，合并正反序样本 | 4699.3 | 4739.1 | 0.85% |

64K 关闭缓存 TTFT 中位数为 **13.946 秒**，开启为 **13.829 秒**。两轮各自结果如下，避免仅靠合并中位数掩盖顺序影响：

| 测试顺序 | 关闭缓存 token/s | 开启缓存 token/s | 缓存收益 |
| --- | ---: | ---: | ---: |
| 先开后关，各 3 次 | 4704.9 | 4754.1 | 1.04% |
| 先关后开，各 5 次 | 4685.5 | 4729.1 | 0.93% |

64K 原始样本按执行顺序：

- 关闭：4726.5, 4704.9, 4695.2, 4714.8, 4703.3, 4685.5, 4681.2, 4669.3。
- 开启：4775.4, 4754.1, 4742.9, 4754.0, 4735.3, 4729.1, 4722.3, 4713.4。

单轮连续请求存在向下漂移，正反序结果是本次贡献判断的依据；不把不足 2% 的差距描述成所有机器和负载的固定收益。原报告的 **4738 token/s** 是另一轮带缓存复测的实测值，不能直接换标签充当关闭缓存的成绩。

## 条件与覆盖

- GLM-5.3-Flash EXL3 4.05bpw，GPU0–2 为 CMP 170HX / SM80，GPU3 为 RTX PRO 6000 Blackwell / SM120。单机 PCIe，GPU 间拓扑为 NODE，同一 NUMA 节点；NCCL P2P 禁用。
- TP1、PP4，实际 decoder 层索引固定为 0–10、11–21、22–32、33–44，即 `11/11/11/12`。B1，生成 32 token，每 rank KV 8 GiB，max length 66560，无 prefix-cache 命中。
- 相同 checkpoint、token IDs、实验库和计算源码。专家采用 `m64n128k64`、阈值 4096、chunk/workspace 6144；普通 INT8 GEMV 2，混合专家 decode 保持生产配置。GPU3 保留原专家路径。
- 顺序为开缓存全长度、关缓存全长度、关缓存 64K、开缓存 64K。每种输入形状预热 2 次；每组启动独立引擎，使关闭组确实不分配缓存。
- 关闭组各 rank 的 `linear_cache` 均为 `None`，SM80 的 INT8 backend 调用仍存在，两个 GEMM 形状均记录 IMMA。开启组确认缓存命中及实际分配量。
- **34/34 访问码检查通过**。这验证指定检索答案，不等同于完整长上下文质量评测；本轮未新增 GSM8K 对照。

## 为什么可以去掉

这份缓存由 `benchmarks/kernels/exl3_prefill/linear_cache.py` 在加载时展开普通量化投影权重。它覆盖注意力投影、共享专家等被预算选中的 Linear，输入行数达到 1024 才使用缓存；B1 decode 仍走原量化路径。

它与 INT8 MoE 专家的临时权重重建和 grouped IMMA 没有依赖关系。移除后，普通投影恢复原 EXL3 实现，专家优化继续生效。完整请求收益约 1%，因此它的显存成本不适合推荐组合。

| GPU | 省去的常驻 FP16 权重副本 |
| --- | ---: |
| GPU0 / SM80 | 3.867 GiB |
| GPU1 / SM80 | 3.113 GiB |
| GPU2 / SM80 | 3.113 GiB |
| GPU3 / SM120 | 0 |
| 合计 | **10.094 GiB** |

这是直接记录的权重副本分配量，不是整进程峰值显存下降量。新 INT8 专家的临时缓冲、原专家 workspace 和 KV cache 仍需要保留。

先前两组独立历史对照也支持收益偏小：M32/K16 + chunk 2048 在 64K 从 4093.9 到 4164.5 token/s（+1.73%）；专家展开 FP16 + chunk 8192 从 4405.4 到 4419.4（+0.32%）。这些不同配置的比例不替代上面的最终 INT8 消融。
