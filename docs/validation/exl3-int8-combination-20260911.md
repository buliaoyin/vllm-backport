# EXL3 优化组合与普通 INT8 GEMV 对照（2026-09-11）

后续已将混合专家 decode 纳入生产默认值，见[默认路径验证](exl3-hybrid-default-20260911.md)。本文保留当时普通 GEMV 0/2 的实验条件和结论。
本轮只改变普通线性层的 `EXL3_INT8_GEMV=0/2`。MoE 两组均启用安全 M32 prefill、chunk/workspace 2048、优先调度和混合专家 decode（SM80 普通 INT8、SM120 激活残差补偿）。因此 `0` 组仍含专家 INT8，结果衡量的是普通 GEMV 在既有优化上的额外收益。

## 测试条件

- Dense：指定 Qwen3.8-27B EXL3，物理 GPU3 RTX PRO 6000 Blackwell；MoE：指定 GLM-5.3-Flash EXL3，GPU0–2 CMP 170HX，GPU3 Blackwell。完整 checkpoint 路径在原始 JSON。
- MoE 固定 `11/11/11/12`，实际层索引为 0–10、11–21、22–32、33–44；逐进程断言通过。SM120 prefill 保持上游实现。
- Torch 2.13.0+cu130、CUDA 13.0、ExLlamaV3 1.4.8。每组独立启动并捕获 CUDA Graph；测试期间运行时代码固定，库哈希和实际专家模式已审计。
- 顺序为每个模型 `0 前测 → 2 → 0 后测`；前两组每项 1 次预热、5 次重复，后测 1 次预热、3 次重复。基线为前后 8 个样本合并中位数，候选为 5 个样本中位数。
- MoE KV 每 rank 8 GiB、最大长度 66560；dense KV 2 GiB、最大长度 4096。max_num_seqs=4，greedy，prefix caching 关闭，所有缓存命中为 0。
- B1 decode TPS = `(输出 token 数−1)/(最后 token 时间−首 token 时间)`。输入 TPS = `输入 token 数/TTFT`，包含调度与首 token 开销。长输入生成 32 token，256/2048 B1 生成 256 token；B4 每请求 128 token。
- 精度使用相同 64 道 GSM8K，逐请求 **B1**，初始最多 768 输出 token。dense 对任一模式触及上限的题目取并集，以同样 B1 设置在 0/2 两组统一提高到 2048 token 补测。与此前 B4 64 题得分不直接比较。原始输出、token ID 和错题均保留。
- GPU 测试串行；CUDA 编译不与性能计时重叠。核函数追踪沿用此前已验证的普通 GEMV 路径，本轮不向计时进程注入追踪。

## B4 与运行漂移

B4 的请求 decode 区间包含 PP 调度和其他请求的 prefill；不能称为固定 M=4 的纯稳态 decode。这里列完整 generate 的输出吞吐（包含 prefill），并保留样本范围。

| 模型 | 输入/请求 | 0 中位数 [范围] | 2 中位数 [范围] |
| --- | ---: | ---: | ---: |
| dense | 2048 | 124.01 [123.63, 124.50] | 123.47 [123.12, 123.67] |
| moe | 256 | 64.27 [62.10, 64.42] | 64.81 [64.45, 67.27] |
| moe | 2048 | 35.85 [35.83, 42.24] | 36.49 [36.48, 36.50] |

MoE 2048-token B4 的前后控制组存在明显调度波动，不能根据中位数宣称稳定收益。单请求则对前、后两个控制组均有提升。完整前后统计和原始样本见机器可读汇总。

## 精度

先列固定 768-token 预算的原始结果；dense 截断题不能当作已完成答案评价。

| 模型 | 0 正确题数 | 2 正确题数 | 2 新错题 ID | 2 修正题 ID | 最终答案相同 | token 序列完全相同 |
| --- | ---: | ---: | --- | --- | ---: | ---: |
| dense | 60/64 | 60/64 | [] | [] | 60/64 | 34/64 |
| moe | 62/64 | 63/64 | [12] | [9, 53] | 61/64 | 19/64 |

Dense 延长输出补测覆盖两组共同的题目并集 [12, 37, 45, 62]，0/2 仍触及上限的题数分别为 1/1。替换这些题目的结果后，0 为 **62/64**，2 为 **62/64**；新错题 [62]，修正题 [45]，最终答案相同 61/64，完整 token 序列相同 34/64。原始 768-token 得分与延长预算结果均保留，不能混用。重启后生成路径也可能发生变化；这组补测不能消除运行非确定性或将全部答案差异归因于 INT8。 补测中 0 的第 45 题、2 的第 62 题分别因截断失败，这两题的得失不能当作纯数值准确率变化。

MoE 8K–64K 固定访问码检索检查 **52/52**。仅验证本次指定访问码，不代表完整长上下文能力评测。

这些结果没有显示模型输出崩坏，但量化会改变输出路径，并存在新增错题。64 题小样本不能证明精度无损、总体精度提升或不存在其他回归。没有运行完整 GSM8K、困惑度或其他学科评测。

## 综合默认参数

本次将先前要求的 M32 与 2048 落地为运行时默认值。普通 GEMV 保留上游默认 2；混合专家 decode 与 INT8 prefill 仍是显式实验路径。

| 参数 | 默认/建议 | 依据及范围 |
| --- | --- | --- |
| `VLLM_EXL3_MOE_M_TILE` | `32` | SM80、uniform 4-bit mul1、维度为 256 的倍数且在 [256, 8192] 使用已验证的安全 M32 FP32 累加内核；其他情形使用上游。设 `16` 可回退。 |
| `max_num_batched_tokens` | 未指定时 `2048` | EXL3 专用默认；保留用户显式设置和调度模式既有调整。此前同组合相对 1024：8K 输入 TPS −5.9%，16K/32K/64K +2.5%/+8.3%/+11.2%。侧重 8K 延迟可显式选 1024。 |
| `VLLM_EXL3_MOE_MAX_TOKENS` | `2048` | 专家 workspace 上限，同时受调度 token budget 限制。GLM 每卡主 workspace 为 384/384/384/1104 MiB，SM80 M32 另共享约 4 MiB 锁缓冲。 |
| `VLLM_EXL3_MOE_PRIORITY` | `1` | 保留此前验证的专家优先调度。 |
| `EXL3_INT8_GEMV` | 保留上游 `2` | Dense B1 +11.5%，MoE 优化组合 B1 约 +2%；存在量化误差和输出差异，不能承诺无损。严格参考检查设 `0`。本轮没有再次测试模式 1，不能将历史小样本结果当成本组合精度保证。 |
| 混合专家 decode | 显式实验开关 | 本文主性能表依赖该路径；当前正常模型启动仍用上游专家 decode。此次未把实验库及 worker 自动纳入生产默认。 |
| INT8 Tensor Core prefill | 显式实验开关 | 默认 M32 保持 FP16 operands、FP32 累加；此前 INT8 prefill 收益不足以支持替换默认。 |

如果需要排除激活 INT8，除了普通 `EXL3_INT8_GEMV=0`，也须关闭实验性专家 INT8。当前 64 题检查没有支持“无精度损失”的证据，也不足以判断不同模式的总体准确率优劣。

M32 通过独立的 PyTorch stable API 组件 `_exl3_C` 集成，使用显式 Tensor 锁缓冲，不依赖实验 worker 或上游私有 `DevCtx` ABI。标准根 CMake 和独立组件两种构建/安装均通过；打包包含上游 MIT 许可证。新组件与已验证实验版本的 6560 条计算 SASS 指令一致。这是计算代码的一致性证据，host 分派还单独经过以下测试：

- 配置回归 **5 项通过**：EXL3 隐式 2048、显式 1024/4096 保留，其他格式默认不变。
- SM80 **95 项通过**：包括新增 M32 尾部、2048 容量溢出、独立权重重建参考与变化输入/路由的 CUDA Graph 重放；新用例明确拒绝误回退上游。
- 实际默认模型启动不传 chunk/workspace/M tile 覆盖，也不设普通 INT8 环境变量。确认 chunk=2048、M tile=[32,32,32,16]、workspace=[2048,2048,2048,2048]、PP=[11,11,11,12]。8K/64K 检索 **4/4**，GSM8K B1 **64/64**，截断 **0**，错题 ID []。

- 当前相关文件的 pre-commit 检查全部通过，见[最终检查日志](exl3-int8-combination-20260911/defaults/precommit-final.log.gz)。
